Additive envelope change (a new optional-on-input extension attribute); no existing message becomes invalid.

## Correlation is first-class (normative)

- New CloudEvents extension attribute **`correlationid`** (lowercase on the wire). Commands may carry it — when absent, the server adopts the command's `id`. The `201` response echoes the effective value as `correlationId`.
- Every event produced by processing a command **must** carry `correlationid` set to that command's correlation identifier; spontaneous events may omit it. Follow-up commands in the same business process should propagate it, so one identifier traverses a chain of services.
- The `?correlationId=` filters on `GET /events` and `GET /events/stream` now match this envelope attribute. `id` remains the idempotency key — correlation and idempotency are now cleanly separate concerns.
- See [design decisions](https://behavioralstate.io/specs/design-decisions) and [MIGRATION.md](https://github.com/behavioralstate/spec/blob/main/MIGRATION.md#migrating-from-091-to-092).

## Removed — webhook subscriptions

- `POST /subscriptions` and `DELETE /subscriptions/{id}` are gone, with the subscription schemas, the `push.webhook` manifest flag, the service descriptor's `webhook` field, and the webhook SSRF security section. The channel promised HMAC-signed delivery whose signature scheme was never specified, and had no known consumer.
- Push delivery is **SSE + MCP notifications**; polling `GET /events` remains the universal fallback. A future need for push-to-disconnected-services would adopt the CNCF CloudEvents HTTP webhook delivery spec as an extension.

## Removed — gRPC transport declaration

- The `grpc` transport block is deleted from the discovery schema. BEST never defined a normative gRPC binding, so no conformant implementation can have depended on it. Same rationale as the A2A removal in 0.8.0.

## Cleanup & editorial

- Residue of previously removed capabilities deleted: the memory/registry/lifecycle tombstone pages and the historical `memory.json` schema. The registry naming vocabulary lives on in the [composing-processes worked example](https://behavioralstate.io/specs/composing-processes).
- `specs/` pages slimmed to concise references now that `SPEC.md` is canonical (~1,400 lines removed; all page URLs unchanged).
- Introductions (README, SPEC.md, overview, website hero) reframed around the core problem: agents discovering capabilities across heterogeneous systems, expressing intent, observing events, and correlating outcomes without bespoke integrations.
