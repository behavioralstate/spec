Clarification-and-addition release on workflow discoverability — **one mechanism, stated once**. No removals; 0.9.4 servers remain conformant. Migration notes: [MIGRATION.md — 0.9.4 → 0.9.5](https://github.com/behavioralstate/spec/blob/main/MIGRATION.md#migrating-from-094-to-095).

## The `workflows` cross-link becomes the single discoverability mechanism

Live agent testing showed that spreading the recipe pointer across prose and structure still left catalogue-first consumers reconstructing multi-step choreography from raw schemas. 0.9.5 consolidates:

- The **`workflows` array** (ids of the recipes an operation participates in) is carried on **both** surfaces that describe an operation: its catalogue entry (as in 0.9.4) **and its schema document** as a top-level member (`GET /commands/{schema}/{version}`, `GET /queries/{schema}/{version}`) — JSON Schema tolerates unknown keywords, and BEST names this one. Both surfaces must carry the same ids.
- Consumers **should** fetch the referenced recipe before composing a multi-step sequence themselves.
- **Prose has no discoverability role.** 0.9.4's suggestion that schema-document descriptions additionally name the recipe is withdrawn — descriptions may mention recipes, but the cross-link array is the mechanism, and there is no other. One field to emit, one field to audit.

Updated: SPEC.md (Workflows, Commands and Queries schema-document sections), `specs/agents/workflows.md` (Discoverability rewritten around the single mechanism), `queries.json` (`workflows` on the query schema document), catalogue-entry field descriptions, Composing Processes guide.

## Tooling (released separately, referenced here for the record)

- `@behavioralstate/best-mcp` 2.3.2 — when a fetched command/query schema document carries (or its catalogue entry names) `workflows`, the client appends a deterministic read-the-recipe note to the tool result, so the nudge reaches the model mechanically rather than relying on prose salience.
