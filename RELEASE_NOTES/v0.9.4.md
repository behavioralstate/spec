Additive release — **workflows become a standard capability**. No wire format changes; nothing a 0.9.x client sends becomes invalid, and servers that publish no workflows change nothing. Migration notes: [MIGRATION.md — 0.9.x → 0.9.4](https://github.com/behavioralstate/spec/blob/main/MIGRATION.md#migrating-from-09x-to-094).

## Added — `io.best.agents.workflows` (Extended tier, optional)

The descriptive-sequence pattern — previously a vendor-extension convention at `GET /workflows` under implementer-owned namespaces — is promoted to a standard optional capability. The promotion was driven by observed agent behaviour: the pattern's reference-client support (`best-mcp get_workflows`) and production deployments had outrun the spec, and naive LLM agents were failing to discover recipes at all because nothing in the standard surface pointed at them.

- **Index/detail split**: `GET /workflows` returns a shallow index (`id`, `name`, `description` — never the steps) so an agent can hold the whole list in one read; `GET /workflows/{id}` returns one full recipe. Fixes the all-or-nothing payloads observed in the wild.
- **Normative step shape**: `kind` (`command`/`query`), `dataschema` (resolvable URI into the live catalogue — recipes reference contracts, never duplicate them, so they cannot drift), `optional`, `guidance`.
- **Catalogue cross-links**: command and query catalogue entries gain an optional `workflows` array naming the recipes each operation participates in — servers **should** populate it, so catalogue-first consumers (which is every LLM agent) discover recipes instead of reconstructing choreography from raw schemas.
- **Scope boundary unchanged**: the capability is strictly descriptive. Executing, retrying, persisting, or branching steps server-side remains out of BEST scope.

New: [SPEC.md — Workflows](https://github.com/behavioralstate/spec/blob/main/SPEC.md#workflows--iobestagentsworkflows), [specs/agents/workflows.md](https://behavioralstate.io/specs/agents/workflows), `protocol/v1/schemas/agents/workflows.json`, OpenAPI paths, conformance rows, and the manifest example entry. The [Composing Processes](https://behavioralstate.io/specs/composing-processes) guide's Pattern 2 now defers to the capability.

## Tooling (released separately, referenced here for the record)

- `@behavioralstate/best-mcp` 2.3.0 — `get_workflows` gains an optional `workflow_id` parameter (`GET /workflows/{id}`); handles both the new index shape and pre-0.9.4 full-list responses.
