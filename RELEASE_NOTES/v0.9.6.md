Additive release — the **`impact` annotation** gives high-impact commands a machine-readable marker. No removals; 0.9.5 servers remain conformant. Migration notes: [MIGRATION.md — 0.9.5 → 0.9.6](https://github.com/behavioralstate/spec/blob/main/MIGRATION.md#migrating-from-095-to-096).

## High-impact commands become discoverable

Since 0.9.1 the Security Requirements have obliged servers to place extra controls on destructive, irreversible, or compliance-bypassing commands — but nothing in the catalogue told a *client* which commands those were, so only the server half of the obligation was implementable. Deploying agent-facing surfaces over real brokerage operations made the gap concrete: an agent discovering `submit-order` from the catalogue had no structural signal that it moves real money.

0.9.6 adds the optional **`impact`** object to command catalogue entries and, following the `workflows` two-surface precedent, as a top-level member of the command's schema document (both surfaces must agree):

- `categories` (required) — `financial`, `destructive`, `irreversible`, `compliance`; open vocabulary, unknown values treated as high-impact.
- `confirmation` (required) — `required`: a consumer acting on behalf of a human **must not** submit without explicit, per-submission confirmation from that human; `recommended`: confirm unless durably pre-authorized.
- `warning` (optional) — text the consumer **should** surface to the human, substantially intact, before asking.

The annotation is **descriptive, not enforcement**: it is the discovery half of the Security Requirements' high-impact controls and never substitutes for them — a server cannot rely on clients honoring it. Service-to-service automation with no human principal remains governed by the server-side controls alone.

## Tooling (released separately, referenced here for the record)

- `@behavioralstate/best-mcp` ≥ 2.3.4 — when a fetched command schema document (or its catalogue entry) carries `impact`, the client appends a deterministic warn-and-confirm note, including the server's `warning` text, to the tool result — the same mechanical-nudge channel the `workflows` cross-link uses.
- `@behavioralstate/best-validate` — schemas resynced; prior releases fail a catalogue that carries `impact` (`additionalProperties: false`), so validate 0.9.6 servers with the matching validator.
