**What the first implementation proved the spec lacked** ([#37](https://github.com/behavioralstate/spec/issues/37)). best-peer, a BEST door in front of GPU machines, was built from the spec text alone; every place the text was silent or ambiguous became an entry on #37, with what best-peer does and the sentence the spec could gain. This release writes those sentences: thirty-eight entries, each named in the commit that settles it. No manifest changes, and no change to the sign-in guidance's words.

## Commands

- **A command the service cannot honour now is refused at ingest** ([Ingestion Semantics](../SPEC.md#ingestion-semantics), step 4): `400` with a code that names the condition and `details` a program can act on, its `id` left free for the corrected retry. A refusal for a state that will pass by itself should say when, where the service knows, as `until` (RFC 3339), with the `reason` where one was given; capacity that is only busy lets the command wait.
- **Commands that wait** ([Commands That Wait](../SPEC.md#commands-that-wait)): a service may accept a command before there is room for it. The caller asks to wait by naming a bound, the wait is told as an event, a bound the service sets is told, and a command that never runs ends in an outcome.
- **Idempotency** belongs to the credential that sent the command, within a retention window the service states. A duplicate is rejected with `409` naming the `id`, or answered as the original was, with its status, `id` and `correlationId`. A body with a `Content-Type` the server does not take is `415`.
- **A command answered `201` is processed across a restart**, or its failure is published; never dropped.
- **Correlation**: a correlation id belongs to the sender that first used it, and another sender's command naming it is refused. Every later fact about what a command created carries its correlation id, for as long as the thing lives.
- **`completes`** on a command's schema document lists the events after which its outcome is known, a failure as much as a success; progress on the way may carry `progress_pct`.
- **A field marked `writeOnly`** (a credential, a URL that grants access by itself) is taken at admission and never recorded, replayed or emitted.

## Events and queries

- **`GET /events` is the log and nothing else**: there is no event catalogue. An event's schema is found from its `dataschema`, and its type from the `produces` of the command that raises it.
- **A `Last-Event-ID` the server never told**, or no longer holds, resumes the stream from now.
- **`from` and `to` are RFC 3339**, the form of every other time in the spec, as is the envelope's `time`.
- **A reading that changes by itself** (a device's free memory, whether its owner is using it) may be a query rather than an event, and should be where the log would otherwise keep personal data about someone who is no party to the commands.
- **Forgetting content** ([Forgetting Content](../SPEC.md#forgetting-content)): a holder may forget what it sent or was told. The envelope stays on every read path, the event says `forgotten: true`, and the completing event names what was removed and what was kept.
- **A query's `parameters` schema governs** what it accepts, each value a string; a query with none ignores what it is sent.
- **A workflows capability is `active`** only while it publishes a recipe, and `planned` with none.

## Sign-in, credentials and tenants

- **The token answer**: `token_type` says how the credential travels (`Bearer`, or `apikey` in `auth_header`). `tenant_id` is absent when the credential opens no single account, and the root then lists the tenants it opens. The credential block's `ready_check`, `http` and `mcp` members have their shapes, and a connection named after its sign-in manifest keeps the port.
- **A credential that ends** ends its open streams. An approver's bound on its life is told in `expires_in`, never shortened. When the approver, or whoever controls the service, takes it back, the service should end the work it started and may let the approver keep it running; a credential its agent revoked itself, or one that ran out, must not end that work.
- **A late poll with an expired `device_code`** should be told `expired_token` for as long as the code lived, and a service should bound pending registrations per network origin too.
- **Tenants**: a root that is itself a surface lists a credential's tenants through a query of its own catalogue. A root capability is the root's own when its service declares an authentication block. An account's membership may be the service's own commands, with an identity named across accounts by an opaque id.

## best-mcp

- **The entries of one account are one credential** ([MCP transport](../specs/transports/mcp.md)): the service's origin plus the tenant, whatever the entries are filed under, so on a service that holds one key per account a configured key that was replaced heals from a stored sign-in of the same account, and a key issued on any entry is written to all of them.
- **best-mcp 2.6.0**, already published, reaches each tenant a name signed in at a multi-tenant host opens as `<name>/<tenantId>`, and no credential follows a redirect; best-mcp 2.6.1, released just before this one, brings three tool texts in line with it: time ranges in RFC 3339, a correlation id of the caller's own, and untyped events described by the command that produces them.

## Security

- **Cleartext** only on loopback, or where the operator states the network encrypts the hop; refused elsewhere, outbound calls that carry a credential included.
- **A record of the requests a service answers**: a service should keep one that names the verified principal, and must never put in it a credential, a header carrying one, or a query string.
- **Pacing** is `429` with `Retry-After`, never counting a retry or a refusal. A service may bound the event streams a client holds, ending the oldest. A body refused for its size says `details.limit_bytes`.

## Required from 0.10.0

Conformance gains item 12 (a correlation id bound to its first sender) and item 13 (every obligation the text marks *Required from 0.10.0*), and Root Manifest Rule 8 (a root credential's tenants listed at the root): see [Conformance](../specs/conformance.md). *Required from 0.10.0* dates when an obligation binds; it plans no release. As before, a version states them first, and validators report them as warnings until they bind. best-validate does not check them yet: [#119](https://github.com/behavioralstate/spec/issues/119).

## Open

On #37, entries 53 to 58 are questions no implementation has answered yet, among them how a client finds a root's tenant-listing query, a correlation that outlives its credential, and the shortest retention of an idempotency key. Entry 59 (`/metrics` beside the BEST surface) closed as the implementation's own, since a reading is a query and a series is the collector's; entry 60 (a tenant that ends) is being proven in best-peer, and entries 45, 47 and 48 wait on the owner's decision. Each reaches the spec once it is settled.
